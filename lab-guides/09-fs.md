# 实验: 文件系统(File System)

在本实验中,你将向 xv6 文件系统添加大文件(large files)和符号链接(symbolic links)。

在编写代码之前,你应该阅读[xv6 手册](../xv6/book-riscv-rev1.pdf)中的"第 8 章:File system",并研究相应的代码。

获取本实验的 xv6 源码并切换到 util 分支:
```
  $ git fetch
  $ git checkout fs
  $ make clean
```

## Large files

在本任务中,你将增大 xv6 文件的最大大小。目前,xv6 文件被限制为 268 块,即 268*BSIZE 字节(xv6 中 BSIZE 为 1024)。这个限制源于这样一个事实:xv6 的 inode 包含 12 个"直接(direct)"块号和一个"单级间接(singly-indirect)"块号,后者指向一个最多能容纳 256 个更多块号的块,总计 12+256=268 块。

bigfile 命令会创建它所能创建的最长文件,并报告该大小:
```
$ bigfile
..
wrote 268 blocks
bigfile: file is too small
$
```
该测试失败是因为 bigfile 期望能够创建一个具有 65803 块的文件,但未修改的 xv6 将文件限制为 268 块。

你将修改 xv6 文件系统代码,以支持每个 inode 中的一个"双级间接(doubly-indirect)"块,它包含 256 个单级间接块的地址,而每个单级间接块最多可以包含 256 个数据块的地址。结果是,一个文件将能够由最多 65803 个块组成,即 256*256+256+11 块(是 11 而不是 12,因为我们将牺牲一个直接块号给双级间接块)。

### 预备知识

mkfs 程序创建 xv6 文件系统磁盘镜像,并决定文件系统总共有多少块;这个大小由 `kernel/param.h` 中的 FSSIZE 控制。你会看到本实验仓库中的 FSSIZE 被设置为 200,000 块。你应该在 make 输出中看到来自 mkfs/mkfs 的如下输出:
```
nmeta 70 (boot, super, log blocks 30 inode blocks 13, bitmap blocks 25) blocks 199930 total 200000
```
这一行描述了 mkfs/mkfs 构建的文件系统:它有 70 个元数据块(用于描述文件系统的块)和 199,930 个数据块,总计 200,000 块。

如果在实验过程中的任何时候你发现自己必须从头重建文件系统,你可以运行 `make clean`,它会强制 make 重建 fs.img。

### 应该看什么

磁盘上 inode 的格式由 `fs.h` 中的 `struct dinode` 定义。你特别感兴趣的是 `NDIRECT`、`NINDIRECT`、`MAXFILE`,以及 `struct dinode` 的 `addrs[]` 元素。查看 xv6 教材中的图 8.3,了解标准 xv6 inode 的图示。

在磁盘上查找文件数据的代码位于 `fs.c` 的 `bmap()` 中。看一下它,确保你理解它在做什么。`bmap()` 在读取和写入文件时都会被调用。写入时,`bmap()` 按需分配新块来存放文件内容,并在需要时分配一个间接块来存放块地址。

`bmap()` 处理两种块号。参数 `bn` 是一个"逻辑块号(logical block number)"——文件内的一个块号,相对于文件的开头。`ip->addrs[]` 中的块号,以及传给 `bread()` 的参数,都是磁盘块号。你可以把 `bmap()` 看作是把文件的逻辑块号映射到磁盘块号。

### 你的任务

修改 `bmap()`,使它除了直接块和单级间接块之外,还实现一个双级间接块。你将不得不只保留 11 个直接块,而不是 12 个,以便为新的双级间接块腾出空间;你不允许改变磁盘上 inode 的大小。`ip->addrs[]` 的前 11 个元素应该是直接块;第 12 个应该是单级间接块(和当前的一样);第 13 个应该是你新的双级间接块。当 bigfile 写入 65803 个块且 usertests 成功运行时,你就完成了本练习:
```
$ bigfile
..................................................................................................................
wrote 65803 blocks
done; ok
$ usertests
...
ALL TESTS PASSED
$
```
bigfile 至少需要一分半钟才能运行。

提示:

- 确保你理解 `bmap()`。画一张图,表示 `ip->addrs[]`、间接块、双级间接块及其指向的单级间接块,以及数据块之间的关系。确保你理解为什么添加一个双级间接块会使最大文件大小增加 256*256 块(实际上应该是 256*256-1,因为你必须将直接块的数量减少一个)。

- 想想你将如何用逻辑块号来索引双级间接块,以及它所指向的间接块。

- 如果你修改了 `NDIRECT` 的定义,你可能必须修改 `file.h` 中 `struct inode` 的 `addrs[]` 声明。确保 `struct inode` 和 `struct dinode` 的 `addrs[]` 数组具有相同数量的元素。

- 如果你修改了 `NDIRECT` 的定义,确保创建一个新的 fs.img,因为 mkfs 使用 NDIRECT 来构建文件系统。

- 如果你的文件系统进入坏状态(也许是由于崩溃),删除 fs.img(在 Unix 中删除,而不是在 xv6 中)。make 会为你构建一个新的干净的文件系统镜像。

- 别忘了 `brelse()` 每一个你 `bread()` 的块。

- 你应该只在需要时分配间接块和双级间接块,就像原始的 `bmap()` 那样。

- 确保 itrunc 释放文件的所有块,包括双级间接块。

## Symbolic links

在本练习中,你将向 xv6 添加符号链接。符号链接(或软链接,soft links)通过路径名引用一个被链接的文件;当符号链接被打开时,内核会沿着链接跟踪到被引用的文件。符号链接类似于硬链接(hard links),但硬链接只能指向同一磁盘上的文件,而符号链接可以跨越磁盘设备。尽管 xv6 不支持多个设备,但实现这个系统调用是理解路径名查找如何工作的一个好练习。

### 你的任务

你将实现 `symlink(char *target, char *path)` 系统调用,它在 path 处创建一个指向名为 target 的文件的新的符号链接。更多信息请参见 man page `symlink`。为了测试,把 symlinktest 添加到 Makefile 并运行它。当测试产生以下输出(包括 usertests 成功)时,你的解决方案就完成了。
```
$ symlinktest
Start: test symlinks
test symlinks: ok
Start: test concurrent symlinks
test concurrent symlinks: ok
$ usertests
...
ALL TESTS PASSED
$
```
提示:

- 首先,为 symlink 创建一个新的系统调用号,在 `user/usys.pl`、`user/user.h` 中添加条目,并在 `kernel/sysfile.c` 中实现一个空的 sys_symlink。

- 在 `kernel/stat.h` 中添加一个新的文件类型(T_SYMLINK)来表示符号链接。

- 在 `kernel/fcntl.h` 中添加一个新的标志(O_NOFOLLOW),它可以与 open 系统调用一起使用。请注意,传给 open 的标志是通过按位或(bitwise OR)运算符组合的,所以你的新标志不应与任何现有标志重叠。一旦你把 user/symlinktest.c 添加到 Makefile 中,这将使你能够编译它。

- 实现 `symlink(target, path)` 系统调用,在 path 处创建一个指向 target 的新的符号链接。请注意,target 不必存在,系统调用也能成功。你需要选择某个地方来存储符号链接的 target 路径,例如,存储在 inode 的数据块中。symlink 应该返回一个表示成功(0)或失败(-1)的整数,类似于 link 和 unlink。

- 修改 open 系统调用,以处理路径指向符号链接的情况。如果文件不存在,open 必须失败。当进程在传给 open 的标志中指定了 O_NOFOLLOW 时,open 应该打开符号链接本身(而不是跟随符号链接)。

- 如果被链接的文件也是一个符号链接,你必须递归地跟随它,直到到达一个非链接的文件。如果这些链接形成环(cycle),你必须返回一个错误码。你可以近似地这样做:如果链接深度达到某个阈值(例如 10),就返回一个错误码。

- 其他系统调用(例如 link 和 unlink)不得跟随符号链接;这些系统调用操作的是符号链接本身。

- 在本实验中,你不必处理指向目录的符号链接。
